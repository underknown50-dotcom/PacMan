# Pac-Man 42

## Description

Pac-Man 42 is a keyboard-controlled arcade maze-chase game written in Python
3.10+ with a restricted pygame frontend. The player clears ten progressively
larger mazes generated by the assigned `mazegenerator` 2.1.0 wheel, collects
pacgums and corner super-pacgums, evades or hunts four ghosts with distinct
arcade personalities, and records completed runs on a persistent top-ten
leaderboard.

```text
Main Menu -> Start Game -> Playing (10 levels) -> Victory / Game Over
          -> Enter Name -> Save Highscore -> Main Menu
```

## Instructions

### Install and Run from Source

Requirements: Linux graphical desktop, Python 3.10+, `venv`, `pip`, and `make`.

```bash
make install
make run
```

Or run directly inside the virtual environment:

```bash
source .venv/bin/activate
python3 pac-man.py config.json
```

The program takes **exactly one argument**: the path to a JSON configuration
file. Missing or extra arguments, unreadable files, or malformed JSON exit
cleanly with a readable `ERROR:` message and zero Python traceback. Full
diagnostic tracebacks are written to
`~/.local/share/forty-two-pacman/errors.log` (rotating at 1 MiB, 3 backups).

### Controls

| Context | Keys | Action |
| --- | --- | --- |
| Menus | `Arrows` or `W`/`S`, `Enter`/`Space` | Navigate & confirm |
| Main Menu | `Esc` | Exit |
| Playing | `Arrows` or `WASD` | Move (with corner turn buffering & instant 180° reversal) |
| Playing | `Esc` or `P` | Pause (freezes all timers; leaving requires confirmation) |
| Playing | `F1` | Toggle Review / Cheat Mode (`I` god, `N` next level, `G` freeze, `L` +life, `B` boost, `O` power, `C` 1 dot left, `T` 1s timer, `K` lose life) |
| End Screen | Letters, digits, spaces, `Backspace`, `Enter`, `Esc` | Enter 1–10 char name (`Enter` saves, `Esc` saves as `PLAYER`) |

| Command | Action |

Build with `make release`, then launch the packaged build with no Python


## Configuration

See [config.json](config.json) and the commented example
[config.comments.json](config.comments.json). Whole lines starting with `#`
are stripped before JSON parsing (hashes inside quoted strings are preserved).
Keys are case-insensitive, unknown keys are ignored, booleans are rejected for
numeric fields, and out-of-range values are clamped to safe bounds with logged
warnings.

| Key | Default | Valid Range / Meaning |
| --- | --- | --- |
| `highscore_filename` | `@userdata/highscores.json` | Safe relative JSON path (defaults to XDG user data) |
| `levels` | 10 default mazes (`19x17` to `27x23`) | Array of 10–100 level objects (`width`/`height` 15–35, optional `level_max_time` 10–3600) |
| `lives` | `3` | Integer `1..99` |
| `pacgum` | `42` | Integer `0..2000` (minimum ordinary pellet count) |
| `points_per_pacgum` | `10` | Integer `0..1,000,000` |
| `points_per_super_pacgum` | `50` | Integer `0..1,000,000` |
| `points_per_ghost` | `200` | Integer `0..1,000,000` |
| `seed` | `42` | Integer `1..2,147,483,647` (fixed for Level 1; later levels use `0` for fresh layouts) |
| `level_max_time` | `180` | Number `10..3600` seconds (shipped levels scale `180s` to `400s`) |
| `power_duration` | `8` | Number `1..60` seconds |
| `ghost_respawn_delay` | `7` | Number `5..10` seconds |
| `player_speed` | `5` | Number `1..15` cells/second |
| `ghost_speed` | `1.5` | Number `0.5..12` base cells/second |
| `pellet_coverage` | `0.8` | Number `0.65..1.0` of eligible corridor cells |

## Highscore

Scores are stored as a human-readable JSON array of up to 10 entries
(`[{"name": "PLAYER42", "score": 1250}]`) in
`$XDG_DATA_HOME/forty-two-pacman/highscores.json` (falling back to
`~/.local/share/forty-two-pacman/highscores.json`). Storing scores in XDG user
data keeps packaged builds working even in read-only installation folders.

To prevent corrupt leaderboards on crash or power loss, `HighScoreStore.save()`
uses **atomic file replacement**: it writes to a temporary file in the same
directory, calls `flush()` and `os.fsync()`, and swaps it in with
`os.replace()`. Ties are broken stably (older score stays ahead).

## Maze Generation

Levels are generated using the unmodified external wheel
`vendor/mazegenerator-2.1.0-py3-none-any.whl` (checksum verified in
[artifact_hashes.json](project_management/artifact_hashes.json)):

```python
from mazegenerator import MazeGenerator

generator = MazeGenerator(
    size=(width, height),
    perfect=False,
    entry_cell=(0, 0),
    exit_cell=(width - 1, height - 1),
    seed=seed,
)
walls = generator.maze
```

`pacman/maze_adapter.py` freezes the returned 4-bit wall grid (`UP=1, RIGHT=2,
DOWN=4, LEFT=8`), checks border and reciprocal wall consistency, builds an
immutable walkable graph (`adjacency`), and selects the largest connected
region (`reachable`) via BFS so sealed `"42"` cells remain visible without
trapping actors or pellets. Pac-Man spawns at the nearest reachable center; the
four ghosts and four super-pacgums occupy distinct corner-region tiles.

## Implementation

- **Fixed-Step Physics (`120 Hz`):** `Game` advances in `1/120` s increments
  (with frame `dt` clamped to `0.25` s), keeping movement independent of display
  refresh rate. `Actor.position()` linearly interpolates between `cell` and
  `target` for smooth 60 FPS motion.
- **Ghost AI:** Four distinct arcade personalities—**Blinky** (direct chase),
  **Pinky** (4 tiles ahead), **Inky** (Blinky reflected across 2 tiles ahead),
  and **Clyde** (chase $> 8$ tiles, retreat home $\le 8$ tiles)—navigating via
  BFS distances without illegal 180° reversals. Super-pacgums invert distance
  selection to flee; eaten ghosts return home as fast harmless eyes.
- **MLX-Equivalent Graphics:** All `import pygame` code is isolated inside
  `pacman/graphics.py`, restricted to operations with MiniLibX equivalents:

| Facade Operation | MiniLibX Equivalent | Implementation |
| --- | --- | --- |
| Window & presentation | `mlx_new_window`, `mlx_put_image_to_window` | `pygame.display.set_mode`, `flip` |
| Image buffers & layers | `mlx_new_image`, `mlx_pixel_put` | `pygame.Surface`, `fill`, `blit` |
| Shapes (lines, circles, polygons) | Custom rasterization into pixel buffers | Bresenham lines, scanline ellipses/polygons (no `pygame.draw` or `pygame.sprite`) |
| Text rendering | `mlx_string_put` | `pygame.font.Font.render` + `blit` |
| Input & loop | `mlx_hook`, `mlx_loop` | `pygame.event.get` + `Clock.tick(60)` |

## General Software Architecture

The project uses a strict **Model-View-Controller (MVC)** layout:
`pacman/models.py` has zero graphics imports, `pacman/rendering.py` is
read-only, and `pacman/app.py` routes events, updates, and rendering.

| Module | Responsibility |
| --- | --- |
| `pac-man.py` | Single-argument CLI, logging setup, and clean error exit |
| `pacman/app.py` | Controller: main loop, screen state routing, keyboard handling |
| `pacman/models.py` | Model: `Actor`, `Ghost(Actor)`, `Game`, collisions, timers, 10 levels |
| `pacman/ghost_ai.py` | Blinky/Pinky/Inky/Clyde targeting and BFS chase/flee selection |
| `pacman/maze_adapter.py` | Unmodified `MazeGenerator` adapter, bitmask graph, BFS distances |
| `pacman/cheats.py` | Resettable `F1` review-mode flags |
| `pacman/graphics.py` | Restricted MLX-equivalent pygame facade & software rasterizer |
| `pacman/rendering.py` | View: menus, HUD, maze, actors, pause, and Victory/Game Over screens |
| `pacman/menu_background.py`, `finish_background.py` | Cached animated twilight/victory/loss backgrounds |
| `pacman/configuration.py` | Comment-aware JSON parser, validation, clamping, safe score paths |
| `pacman/highscores.py` | Top-ten ranking and atomic JSON persistence |
| `pacman/error_logging.py` | Rotating UTC diagnostics file with safe console fallback |
| `pacman/smoke.py` | Headless end-to-end 10-level smoke check (`make smoke`) |
| `pacman.spec`, `build_release.sh` | Repeatable PyInstaller standalone Linux packaging |
